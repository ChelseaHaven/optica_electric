# UART workspace

ROS 2 Jazzy package `serial_bridge`, for the wire protocol in `optic_electric2`.
The package and topic names are generic. The default port is `/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0`.

```bash
source /opt/ros/jazzy/setup.bash
source /home/pi/chenzhihan/optica_electric/uart_ws/install/setup.bash
colcon build --symlink-install
source install/setup.bash
# Start with the default USB serial adapter:
ros2 launch serial_bridge serial_bridge.launch.py
# After connecting the controller, choose the actual port:
ros2 launch serial_bridge serial_bridge.launch.py port:=/dev/ttyXXX
```

The controller USART3 uses 460800 baud, 8N1, no flow control. The selected Linux
port must be available to user pi; UART pin selection and console services have
not been changed. Baudrate can be overridden by the launch argument.
No daemon or automatic startup is installed.

| Direction | Topic | ROS type | Data |
|---|---|---|---|
| Subscribe | `cmd_vel` | geometry_msgs/Twist | linear.x/y m/s, angular.z rad/s; body X forward, Y left, Z up |
| Publish | `/drive/wheel_states` | sensor_msgs/JointState | A/B/C/D wheel angular speeds, rad/s; positions unknown and left empty |
| Publish | `imu/data_raw` | sensor_msgs/Imu | gyro rad/s, acceleration m/s² including gravity; no orientation |
| Publish | `imu/magnetic_field_raw` | std_msgs/Float64MultiArray | XYZ signed magnetic raw counts, LSB |
| Optional publish | `imu/magnetic_field` | sensor_msgs/MagneticField | Tesla, only if a confirmed positive magnetic_scale_t_per_lsb is configured |
| Publish | `serial/status` | std_msgs/String | JSON connection, counts, errors and last sensor ages |

Sensor topics use sensor-data QoS. Do not interpret a successfully opened port as
proof of valid telemetry; check status ages. Sensors are stamped at host reception,
not MCU sampling time; the current firmware protocol does not contain timestamps.
`imu_frame_id` defaults to `imu_link`. Mounting transform and calibration belong to
the upper application. No TF, position integration, localization or wheel geometry
assumptions are implemented. Imu orientation covariance[0] is -1; gyro/accel
covariance zero means unknown, not a measured noise model. Magnetometer counts are
never mislabeled as Tesla. Use model-specific scaling/calibration before fusion.

Outgoing frames use command 0x0101 + three little-endian float32 values at 50 Hz.
Stale commands (default 0.3 seconds), initial connection and reconnect send zeros
until a fresh command arrives. MCU also has its own 500 ms velocity timeout.
A partial write is completed before another frame; no command backlog is replayed.
Shutdown attempts one final stop frame. On OS disconnect/error, retry after 1 s.

Incoming 0x0101 is four float32 wheel speeds; 0x0102 is nine float32 gyro XYZ,
accel XYZ, mag XYZ. Framing: A5, payload length LE16, sequence byte, header CRC8,
command LE16, payload, frame CRC16 LE16. Header CRC uses reflected 0x8c/initial
0xff; frame CRC uses reflected 0x8408/initial 0xffff. These match the firmware.

Configuration: `src/serial_bridge/config/serial_bridge.yaml`. Topics may be remapped
using standard ROS remapping. Restart the node after parameter changes.

Tests, without connecting any hardware:

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash
python3 -m pytest src/serial_bridge/test/test_protocol.py
ROS_DOMAIN_ID=193 python3 src/serial_bridge/test/pty_integration.py
```

Golden frames in `test/firmware_vectors.json` were generated by compiling and
calling optic_electric2's actual C framing and CRC functions. The PTY integration
test runs the real ROS node, verifies velocity commands, stale-command zeroing,
wheel/IMU/magnetic topics, split frames, CRC rejection and disconnection.

Wheel JointState names, in firmware A/B/C/D kinematics order: front_left_wheel, front_right_wheel, rear_left_wheel, rear_right_wheel. The firmware already sends wheel angular velocity in rad/s (encoder counts * 2*pi / 1560 / dt); the bridge forwards these values without multiplying/dividing again. Physical motor wiring must follow this kinematics order.

Default serial port: `/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0`. Start with `ros2 launch serial_bridge serial_bridge.launch.py`; no port argument is needed. Override with `port:=...` when changing adapters. To run idle without opening a port, invoke `ros2 run serial_bridge serial_bridge --ros-args -p 'port:=""'`.
